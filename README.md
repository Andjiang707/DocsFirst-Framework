# 🚀 Docs-First：AI 輔助開發方法論

介紹 **「文件先行」(Docs-First)** 開發模式。
這是針對 **Vibe Coding** 趨勢下，確保 AI 生成程式碼品質的核心方法。
其核心哲學是：**開發者的角色已從「編碼者」轉向「問題定義者」**。

---

## 💡 核心理念：解決 AI 的「知識斷層」與「幻覺」

許多開發者在使用 Cursor、Claude Code 或 Copilot 時常面臨 AI 產出垃圾程式碼的問題，主要源於兩大技術陷阱：

1. **資訊過時 (Outdated)**：未指定版本，導致 AI 預設使用 5 年前的舊套件，無法發揮現代框架的效能。
2. **幻覺式追新 (Hallucinated Newness)**：這是一個更嚴重的問題——當你要求使用最新版本的套件（例如剛發佈半年的框架）時，**AI 的訓練資料庫可能尚未收錄該版本的 API 變更**。
* **後果**：AI 會根據套件名稱「腦補」出看起來很合理、但實際上根本不存在的函數或參數，導致程式碼瘋狂報錯。



**「文件先行」透過建立明確的規格書，強行校正 AI 的行為。**

---

## 🛠 四大核心文件 (The Four Artifacts)

| 文件名稱 | 角色定位 | 解決痛點 | 實作建議 |
| --- | --- | --- | --- |
| **`prd.md`** | **產品需求** | 防止功能遺漏或實作了錯誤的業務邏輯。 | 詳細列出使用者故事、頁面流程與核心功能。 |
| **`techStack.md`** | **技術規範** | **解決版本斷層關鍵。** 避免 AI 使用過時套件或「瞎編」最新套件的語法。 | 除了列出版本（如 Next.js 15），建議貼入**最新官方文件的 API 範例**供 AI 參考。 |
| **`scaffold`** | **專案骨架** | 防止檔案隨機生成，確保目錄符合架構慣例。 | 要求 AI 根據技術棧一次性生成完整結構，而非逐一生成檔案。 |
| **`memory`** | **長期記憶** | 防止 AI 在新對話中「失憶」，忘記專案指令與規範。 | 使用 `CLAUDE.md` 或 `.cursorrules`，記錄常用指令、測試規範與專案慣例。同時定義 **AI Agent 角色**與 **Skills 技能庫**，讓 AI 根據任務階段切換專業角色。 |

---

## 🤖 AI Agent 與 Skills 技能庫（進階框架）

> **注意**：這不是 Claude 的內建功能，而是透過「文件定義」來引導 AI 行為的進階技巧。

為了讓 AI 更精準地執行不同階段的任務，建議在 `CLAUDE.md` 中**自行定義**：

### Agent 角色系統（透過 Prompt 引導）
透過明確的角色描述，讓開發者在不同任務階段給予 AI 更精準的指令，例如：
- **Architect (架構師)**：負責專案初始化與骨架生成
- **Feature Developer (功能開發者)**：實作具體業務邏輯
- **Stylist (樣式工程師)**：處理 UI/UX 與響應式設計
- **Debugger (除錯專家)**：修復 Bug 與效能優化

每個 Agent 都有明確的**職責範圍**、**觸發時機**與**禁止行為**，避免 AI 越權或混淆角色。

### Skills 技能庫（標準化操作模板）
將常見操作模式化為可重用的「技能模板」，透過文件提供明確的執行範例，例如：
- **Generate Scaffold**：根據 `techStack.md` 一次性生成完整專案結構
- **Implement State Management**：使用指定的狀態管理方案（如 Zustand），並提供正確的 API 範例
- **Apply Styling Framework**：遵循設計規範使用 Tailwind 等工具
- **Integrate Third-party Library**：按照官方文件整合外部套件，避免 AI 幻覺

每個 Skill 都包含**輸入/輸出範例**、**參考文件**與**禁止事項**，這些都是**開發者自行撰寫的規範**，用來約束 AI 的行為邊界。

## 🔧 針對「AI 知識不支援」的進階策略

當你必須使用 AI 訓練資料庫之外的最新技術時，請在 `docs/techStack.md` 中採取以下行動：

* **提供 Reference (參考文檔)**：直接將最新版的 API 關鍵語法範例貼在 Markdown 裡。
* **明確禁止行為**：例如「禁止使用 `App Router` 以外的語法」或「禁止使用已被棄用的 `v4` 參數」。
* **版本鎖定**：不僅寫出名稱，更要寫出精確版本號，讓 AI 知道它必須檢索或遵循特定邏輯。

---

## 🔄 標準開發工作流

> **「先寫 Docs，再跑 Init，最後才寫 Src。」**

1. **定義階段 (The Docs)**：撰寫 `prd.md` 與 `techStack.md`。若使用最新套件，務必在此補上 API 範例。
2. **初始化階段 (The Init)**：生成 **Scaffold (腳手架)**，並建立 `CLAUDE.md` 等記憶文件。
3. **開發階段 (The Src)**：AI 依據「文件」提供的正確語法範例進行實作，避免因知識斷層產生的虛假語法。

## 📂 建議專案結構 (Project Layout)

```text
my-project/
├── CLAUDE.md       # AI 記憶文件 (記錄指令、風格、最新 API 避坑指南)
├── docs/           # 指令手冊 (由開發者定義)
│   ├── prd.md      # 產品需求文件
│   └── techStack.md # 技術規範 (含版本鎖定與 API 參考範例)
├── src/            # 原始碼 (由 AI 執行產出)
└── package.json    # 依賴管理

```

## 🎯 結論：精準定義 = 開發力

在 AI 時代，**撰寫程式碼的成本趨近於零，但校正 AI 幻覺的成本卻很高。
** 透過「文件先行」法，你提供的不再是模糊的「感覺 (Vibe)」，而是具備法律約束力般的「藍圖」，這才是實現高效率開發的唯一路徑。
